# 光源与像素效果

从“视图 → 光源与像素...”或骨架属性中的同名按钮打开面板。打开 `samples/lighting-pixels.rig.json` 可查看带点光源、16 色抖动和描边的示例。

## 2D 点光源

启用后可调世界坐标位置、RGB 颜色、半径、强度和环境亮度。光照从中心向外按距离平方衰减，超出半径后只保留环境亮度。它作用于角色已经合成的平面画面，保留透明度；不是法线贴图照明，不产生投影。本阶段提供一个全局光源，不提供光照关键帧。

## 像素效果

- 网格大小为 1–32 个世界单位。网格中心使用最近邻采样，透明度按 128 阈值变成全透明或全不透明，细小细节可能消失。
- 限色支持 1–256 色，可增删、修改颜色，或恢复默认 16 色与四级灰度。
- 有序抖动使用 4×4 Bayer 图案，固定在世界网格上，平移视口不会改变图案。角色运动时，内容仍会跨越固定网格。
- 描边沿透明边缘扩展一个网格单位。启用限色时，描边颜色也会映射到色板内。

光照先于限色和描边执行。两种效果可单独启用，恢复默认会关闭效果。像素模式固定使用 1x 采样，禁用导出超采样；导出比例会改变最终每个网格覆盖的像素数，建议使用能得到整数网格尺寸的比例。

## 保存、撤销与导出

参数随工程保存，拖动参数支持成组撤销与重做；源图片不变。普通工程继续保存为 v5，仅使用扩展混合模式时为 v6；修改过光源或像素设置的工程保存为 v7，即使暂时关闭效果也会保留设置。当前读取器支持 v1–v8；使用独立分量动画、关联网格或皮肤独立变形时写 v8。旧版软件会拒绝不支持的版本，需用新版打开。合并到空工程时继承效果，合并到已有工程时保留目标的全局效果并报告差异。

PNG/JPG 序列、精灵表、GIF、视频及 Unity/Godot 帧动画都会烘焙效果，导出背景不受角色光照影响。**需要严格保留色板与透明度时使用透明 PNG**；GIF 会再经过其固定色表量化，JPG 和常见视频编码会改变颜色。纹理打包器仍打包源纹理，不烘焙角色效果。

`.pwframes` 写入 `filter="nearest"`（像素模式）或 `"linear"`。配套 Unity/Godot 插件自动使用相应采样方式；旧清单未写该字段时沿用线性采样。游戏引擎中的非整数缩放仍可能导致像素宽度不均。

## 性能与范围

面板顶部的“效果预览”可选择 **CPU 预览 / GPU 预览**，默认 CPU。选择保存在现有用户 `settings.json` 的 `effectsPreview` 字段，不改动工程内容、工程格式或撤销历史，重启后恢复。恢复默认效果只重置角色效果，不重置预览后端。

GPU 模式使用 OpenGL 3.3 片元着色器处理光照、像素网格、限色、有序抖动与描边，直接显示输出纹理，无逐帧 GPU 读回。角色几何、剪裁和插槽合成仍使用现有 CPU 光栅流程；本阶段没有把整条渲染流水线移到 GPU。GPU 初始化、编译或绘制失败时自动使用 CPU，并在面板与问题面板提示；切换 CPU 后再选 GPU 可重试。失败后保留用户的 GPU 偏好，下次启动重新尝试。

两种模式都缓存静止姿态，预览最长边限制为 2048 像素。GPU 在不同驱动上可能出现细小浮点差异。**图片、视频与引擎资源包始终使用原有 CPU 导出**，按目标分辨率处理；无需给后台导出线程创建 OpenGL 上下文。需要核对最终画面时以导出 PNG 为准。

大画面、播放中的变形和高色数仍会增加开销，复杂角色的总帧率取决于 CPU 合成、上传和 GPU 后期，不能仅凭着色器耗时推断。实际设备的效果处理测量见 [PERFORMANCE.md](PERFORMANCE.md)。资源预算对应 CPU 导出，包含效果图像缓冲，不包含颜色查找缓存、源图片副本、PNG 编码临时内存及引擎开销。

本阶段是角色渲染效果，不包含像素绘画画布、画笔、填充工具、逐帧像素编辑或法线贴图制作。
