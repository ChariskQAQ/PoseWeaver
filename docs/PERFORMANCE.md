# 性能测量

先固定输入并记录耗时，再对慢项做可对比的优化。本轮只建立测量，没有更换渲染器或撤销结构。

## CPU 基准运行

构建 Release 后运行 `build\Poseweaver-Verified\rigcore_bench.exe`，标准输出为 CSV，可重定向到文件；其他构建目录中的同名目标也可运行。`--smoke` 只检查场景有效和输出非空，已接入 CTest，不作为性能达标判断。

绿色版也包含 `rigcore_bench.exe`。在解压目录打开终端运行 `.\rigcore_bench.exe > baseline.csv`，即可记录本机结果。

每阶段预热 10 次，正式采样 120 次，使用 `std::chrono::steady_clock` 记录毫秒，输出平均值、P50、P95、最小值、最大值及场景骨骼/插槽/网格/约束数量。P50/P95 使用排序后的实测样本，不由平均值推算。

| 场景 | 骨骼 | 插槽 | 网格顶点 | 网格三角形 | 变换约束 |
|---|---:|---:|---:|---:|---:|
| small | 33 | 32 | 288 | 256 | 2 |
| medium | 129 | 128 | 3,200 | 4,096 | 8 |
| large_clipped | 513 | 513 | 12,800 | 16,384 | 32 |

每顶点两根骨骼影响，全部骨骼带旋转动画，四种混合模式交替使用。大场景额外使用一个凹多边形剪裁，表中网格顶点数不包含剪裁轮廓的 6 个点。图像为固定 1×1 白纹理，渲染到 256×256 RGBA，覆盖大小和重叠保持不变。

## 测量边界

- `pose`：动画采样、本地/世界变换和变换约束，时间从 0 推进到 119/120 秒。
- `geometry`：固定最后一个姿态，计算所有网格的蒙皮与几何；复用输出容器。
- `clipping`：只在大场景测量；对已计算的几何执行凹多边形剪裁。
- `raster_256`：清空目标、重新生成几何、按工程设置剪裁并绘制，包含前述几何/剪裁开销。不能再与它们相加。
- `snapshot_json`：完整文档压缩 JSON 序列化，与撤销快照使用相同入口；不含撤销列表移动和恢复解析。

以上 CPU 基准不含 GPU、屏幕刷新等待、完整 ImGui 界面、图片解码、磁盘读写、音频、物理模拟、GIF/视频编码。结果不能换算成软件的实时 FPS，也不代表真实项目的整体性能。

## CPU 首份基线

原始结果见 [performance-baseline.csv](performance-baseline.csv)。采集日期为 2026-10-18，来自本工作目录的 Release 构建，MSVC 14.44.35207、Windows 10.0.26300 x64，处理器标识为 `AMD64 Family 25 Model 97 Stepping 2, AuthenticAMD`。记录当前工作区实现，尚未提交为独立 Git 修订。

同机比较应保持 Release、相同样例/尺寸/采样数，关闭额外重负载并连续运行三次，比较中位数和 P95；若差异接近背景波动，不判定为改进。首份数据是一次采样，不设 CI 耗时阈值。

初步观察：大场景的 JSON 快照和剪裁比单独网格计算更值得继续调查。下一轮先采集用户工程与实际交互耗时，验证撤销快照、约束更新和剪裁是否落在卡顿路径。GPU 提交/绘制已补充如下，导出编码尚未测量。本轮不据合成样例直接改架构。

## GPU 基准运行

Release 构建和绿色版均包含 `riggpu_bench.exe`。在工具所在目录运行：

```powershell
.\riggpu_bench.exe > gpu.csv 2> gpu-metadata.json
```

CSV 输出分阶段统计；JSON 记录实际 OpenGL 设备名、厂商、驱动版本、计时器位数、样本数和测量边界。必须检查进程退出码为 0 且 JSON 的 `status` 为 `ok`；失败时 CSV 可能只有部分结果。不支持计时器时退出码为 77，不伪造 GPU 数据。`--smoke` 使用每场景 3 次采样检查真实绘制、计时结果、查询完成和 OpenGL 错误，已接入 CTest；不设置与硬件速度相关的耗时阈值。

复用 CPU 基准的固定工程和编辑器实际 `Editor::drawSlots`、ImGui OpenGL 渲染后端。使用隐藏 OpenGL 3.3 窗口和独立 RGBA8 单采样帧缓冲，以避免隐藏窗口的默认帧缓冲及桌面遮挡影响目标尺寸。场景为 small/medium 的 720p 多模式混合，以及 large_clipped 在 720p/1080p 的多模式和全正常混合，共 6 项。

每场景预热 10 帧、采样 120 帧，姿态固定在 0.25 秒，白纹理为 1×1。按帧分别记录：

- `cpu_draw_list`：构建 ImGui 帧与实际插槽绘制列表，包含网格计算和 CPU 剪裁；不含姿态计算。
- `cpu_submit`：只计 `ImGui_ImplOpenGL3_RenderDrawData` 调用的 CPU 时间，包含缓冲上传、状态切换和绘制命令提交；不含清屏、查询 API、帧尾 flush 和结果读取，因此也不是完整 CPU 帧耗时。
- `gpu_draw`：用 `GL_TIME_ELAPSED` 包围同一渲染调用，读取 64 位纳秒结果后转换为毫秒。所有样本提交后，先检查 `GL_QUERY_RESULT_AVAILABLE` 再读结果，等待不计入 CPU 提交时间。方法依据 [Khronos 的查询对象说明](https://wikis.khronos.org/opengl/Query_Object#Timer_queries)。

每帧结束查询后立即 `glFlush`，把结束标记送入 GPU 队列，再开始下一帧 CPU 剪裁，防止查询区间被下一帧命令提交空档拉长。仅在预热结束时调用一次 `glFinish` 清空预热工作，正式采样期间不强制逐帧等待 GPU。读取 GPU 像素验证确实绘出了内容，读回也不参与计时。

CSV 同时记录实际绘制命令数和回调数。三段时间不应直接相加：CPU 与 GPU 可并行，GPU 区间也可能包含渲染命令之间的依赖及供给空档；它不是 GPU 利用率或完整软件 FPS。未计入完整编辑器界面、桌面合成、屏幕刷新、真实纹理带宽、解码和视频编码，不能据此宣称所有项目均达到某个帧率。

## GPU 首份基线

原始数据见 [gpu-performance-baseline.csv](gpu-performance-baseline.csv)，设备和测量环境见 [gpu-performance-metadata.json](gpu-performance-metadata.json)。同机连续运行 3 次，每项每次 120 帧；保留每次的平均/P50/P95/最小/最大值，不把各次 P95 的平均值当作合并后的 P95。测量时未锁定显卡频率，跨机器、驱动或电源模式应重新采样。

本次设备：`NVIDIA GeForce RTX 5070 Laptop GPU/PCIe/SSE2`，OpenGL `3.3.0 NVIDIA 616.92`，64 位计时器，Release x64。下表每项取三次运行对应统计值的中位数，耗时单位为毫秒。

| 场景 / 分辨率 | 混合 | 绘制次数 | CPU 列表 P50 | CPU 提交 P50 | GPU P50 | GPU P95 |
|---|---|---:|---:|---:|---:|---:|
| small / 1280×720 | 四种交替 | 32 | 0.006 | 0.162 | 0.004 | 0.004 |
| medium / 1280×720 | 四种交替 | 128 | 0.038 | 0.511 | 0.011 | 0.755 |
| large_clipped / 1280×720 | 四种交替 | 402 | 12.146 | 2.168 | 1.506 | 2.368 |
| large_clipped / 1280×720 | 全部正常 | 2 | 12.180 | 0.136 | 0.020 | 0.021 |
| large_clipped / 1920×1080 | 四种交替 | 402 | 12.198 | 1.849 | 0.966 | 2.125 |
| large_clipped / 1920×1080 | 全部正常 | 2 | 12.162 | 0.137 | 0.034 | 0.041 |

这组合成场景中，剪裁场景的 CPU 绘制列表构建明显比 GPU 绘制耗时更长；多种混合交替也显著增加绘制次数和提交耗时。据此可优先调查 CPU 剪裁与混合切换成本，但尚不能把结果推广到真实大纹理或完整编辑器界面。

## 光源与像素效果的 CPU / GPU 对照

2026-10-19 在同一台设备的 Release x64 构建运行 `gpu_effects_tests.exe --measure`。设备为 NVIDIA GeForce RTX 5070 Laptop GPU，OpenGL 3.3.0 NVIDIA 616.92。逐像素回归先覆盖光源、像素化、限色、抖动和描边的组合，包含透明阈值、负坐标、缩放与旋转、1/256 色色板、纹理重建和 OpenGL 状态恢复；允许 RGB 最多 1 个字节值误差，透明度要求完全一致。编辑流程另覆盖后端选择记忆、GPU 错误回退与重试、资源释放，以及选择 GPU 后导出 PNG 与 CPU 选择一致。

测量使用固定的 512×512 合成 RGBA 输入，预热 2 次、采样 9 次，报告中位数；原始汇总见 [effects-performance-baseline.csv](effects-performance-baseline.csv)。CPU 计时包围 `applyRenderEffects`；GPU 计时包含源图上传、参数提交、着色器绘制及 `glFinish` 等待，不包含首次着色器编译、角色几何合成、姿态计算、ImGui 界面或输入图片生成。使用默认 16 色，像素案例开启抖动与描边。

| 512×512 效果 | CPU 处理 / ms | GPU 上传、处理及等待 / ms |
|---|---:|---:|
| 点光源 | 4.2793 | 0.5776 |
| 16 色像素效果 | 18.2291 | 0.8046 |
| 点光源 + 16 色像素效果 | 23.2633 | 0.7691 |

这是一轮效果处理测量，未锁定显卡频率，不设跨设备耗时阈值。GPU 模式仍在 CPU 合成角色画面；上述结果不代表整个编辑器帧率，也不能用于承诺低端或集成显卡的性能。

## 1.0.3 编辑器交互与大纹理测量

2026-10-23 整理本机 Release x64 的前后对照。新增 `rigeditor_bench.exe`，复用编辑器的打开、变换、播放界面、撤销及后台导出入口，使用隐藏 OpenGL 窗口和独立临时工程/用户设置目录。它不保存传入的原工程，测试输出和临时配置在结束后清理。

```powershell
.\rigeditor_bench.exe > editor.csv 2> editor-metadata.txt
.\rigeditor_bench.exe --project "D:\Art\character.rig.json" > project.csv 2> project-metadata.txt
```

默认压力样例为 513 根骨骼、512 个 5×5 蒙皮网格、32 个约束、1 个动作、8 张 2048×2048 图片（128 MiB 源 RGBA）。这是固定合成样例，不代表生产级用户工程；另用随包机器人运行 `--project`，验证实际工程入口。当前没有大型生产工程样本。

测量边界：

- `open`：完整打开和纹理加载，5 次；包含重复读取的文件缓存效果，不能当作冷启动磁盘速度。
- `play_ui_cpu`：5 帧预热后的 60 次姿态及 ImGui 界面构建，1280×800；不包含 OpenGL 绘制提交、GPU 执行和显示呈现，不能据此换算软件实际帧率。
- `drag_update`：Setup 模式下 60 次真实骨骼旋转更新；拖动开始的撤销快照另计。
- `checkpoint` / `undo`：各 5 次，包含当前 JSON 快照与恢复的成本。压力样例的大快照仍有明显停顿，后续需结合真实工程评估。
- `export_start`：只计 UI 启动调用，取消及等待工作线程退出不计入该段。每次启动独立列一行；下表中位数由全部 5 行计算，首次与重复导出另列，避免掩盖首次保存配置的开销。

| 压力样例耗时（ms） | 优化前 | 1.0.3 |
|---|---:|---:|
| 打开，中位数 | 239.447 | 239.371 |
| 播放界面 CPU，中位数 | 9.687 | 9.834 |
| 拖动更新，中位数 | 未测 | 7.140 |
| 创建撤销快照，中位数 | 73.588 | 68.719 |
| 撤销，中位数 | 116.500 | 116.794 |
| 首次启动导出 | 36.298 | 16.820 |
| 5 次启动导出的中位数 | 33.794 | 4.730 |

主要变化是导出共享不可变图片像素、避免重复数据诊断，以及配置未改变时跳过重复磁盘刷新。工程数据仍独立复制，首次或修改配置后仍会保存配置；本次没有整体播放速度或撤销速度提升的结论。未锁定 CPU/GPU 频率，也未控制后台负载，不设置硬件相关耗时阈值。

## 1.1.0 局部撤销（2026-10-28）

沿用上述 512 网格、128 MiB 纹理合成样例。本轮完整快照创建中位数 61.712 ms、撤销 96.898 ms；局部改名记录中位数 0.001 ms，局部骨骼记录与两种局部撤销中位数均低于 CSV 的 0.001 ms 精度。改名记录均值 0.043 ms 含首次清除旧重做历史的成本。低于精度不代表真正耗时为零。

这些数字只覆盖逆操作记录与恢复，不含下一帧界面、约束与 GPU 绘制。结构或复杂补偿仍使用完整快照，因此不能宣称所有撤销都低于 1 ms。未锁频或控制全部后台负载，暂无大型生产用户工程。原始记录见 [局部撤销测量](editor-performance-local-undo.csv) 及 [设备与范围](editor-performance-local-undo-metadata.txt)。
