## 分阶段计划

每个阶段结束时：核心算法有 `rigcore_tests` 覆盖，`--screenshot` 自检截图，README 更新。

### 阶段 1：动画核心
先补核心数据，后面的功能都依赖它。
1. ✅ 核心模型：贝塞尔曲线、斜切（shear，工具 Z）、插槽颜色关键帧、绘制顺序关键帧、事件。
   工程文件格式升级为 version 2，可读取 version 1。
2. ✅ Graph 视图：骨骼通道与插槽颜色曲线、贝塞尔手柄、缩放/平移。
3. ✅ Dopesheet：多选、框选、复制/粘贴、按比例缩放关键帧。
4. ✅ Ghosting（洋葱皮）。
5. ✅ 骨骼/图片补偿。

### 阶段 2：网格与变形
1. ✅ 网格编辑器：外轮廓、增删顶点、约束 Delaunay 三角化、按透明度自动生成轮廓。
2. ✅ 变形关键帧（deform）。
3. ✅ 权重工具补全：平滑、修剪、锁定、数值输入、镜像。
4. ✅ 剪裁附件、边界框附件。工程格式升级为 version 3。

### 阶段 3：约束
1. ✅ 约束框架：姿态分“动画值 local”和“约束后 applied”两层，约束按列表顺序生效；数值可打关键帧。
2. ✅ IK 约束；姿势工具 Ctrl 多选骨骼链用 CCD IK 摆姿势。
3. ✅ 变换约束。
4. ✅ 路径附件与路径约束。
5. ✅ 物理约束（状态由编辑器按时间推进，可烘焙为关键帧）。工程格式升级为 version 4。

### 阶段 4：皮肤 ✅
没有把附件整体搬进皮肤，而是用“皮肤占位”：插槽里的占位附件按名字从激活的皮肤取内容。
这样附件切换 / 变形关键帧仍按插槽附件索引工作，旧工程无需迁移。工程格式升级为 version 5。
已知限制：变形关键帧按占位记录，多个皮肤的网格拓扑不同时只对顶点数相同的皮肤生效。

### 阶段 5：导入导出 ✅
Texture Packer、Export Images（PNG 序列/精灵表/GIF）、Export Video（ffmpeg）、二进制导出、
Import Data / Import Project（合并）、PSD 导入。渲染用 core/raster 的软件光栅化，结果确定且可测试。
命令行：`RigEditor --run <json|bin|atlas|png|jpg|sheet|gif|mp4|webm|avi|mov|merge|psd> <路径>`。

### 阶段 6：音频 ✅
miniaudio 播放与解码（WAV / MP3 / FLAC）；播放时按事件触发声音，从中途开始播放会接上已在进行的声音，
速度改变音调，暂停即停止；Dopesheet 为每个有音频的事件画波形；导出视频时把音频事件混成一条音轨。
波形峰值、混音和 WAV 编码在 core/audio_mix（有单元测试）。

### 补充：动画混合 ✅
core/anim_state 是运行时式的 AnimationState：多轨道按序叠加（高轨道覆盖其关键帧的通道，可设轨道权重），
同轨道切换动画时交叉淡化（旋转走短路径，附件 / 绘制顺序 / IK 弯曲方向在一半处切换，变形与约束值插值），
动画队列（延迟默认相对上一动画结束减去混合时长）、空动画淡出到下层、循环中的事件收集。
编辑器的“混合预览”视图（Dopesheet 旁）驱动视口；任何编辑会自动退出预览。

## 风险与说明

- **皮肤**会改动核心数据结构，越晚做迁移成本越高。所以排在约束之后、导出格式定稿之前。
- **物理约束、路径约束、Graph** 是单项最大的三块，各自需要专门的数值算法与交互。
- **视频导出**依赖用户本机安装的 ffmpeg，编辑器只负责找到它并把帧通过管道传进去。
- **与 Spine 数据格式互通**（读写 Spine 的 JSON）不在本表内，需要另行评估：
  Spine 运行时的许可证要求使用者持有 Spine 授权。
