## 分阶段计划

每个阶段结束时：核心算法有 `rigcore_tests` 覆盖，`--screenshot` 自检截图，README 更新。

### 阶段 1：动画核心
先补核心数据，后面的功能都依赖它。
1. ✅ 核心模型：贝塞尔曲线、斜切（shear，工具 Z）、插槽颜色关键帧、绘制顺序关键帧、事件。
   工程文件格式升级为 version 2，可读取 version 1。
2. ✅ Graph 视图：骨骼通道与插槽颜色曲线、贝塞尔手柄、缩放/平移。
3. ✅ Dopesheet：多选、框选、复制/粘贴、按比例缩放关键帧。
4. ✅ Ghosting（洋葱皮）。
5. ✅ 骨骼/图片补偿。

### 阶段 2：网格与变形
1. ✅ 网格编辑器：外轮廓、增删顶点、约束 Delaunay 三角化、按透明度自动生成轮廓。
2. ✅ 变形关键帧（deform）。
3. ✅ 权重工具补全：平滑、修剪、锁定、数值输入、镜像。
4. ✅ 剪裁附件、边界框附件。工程格式升级为 version 3。

### 阶段 3：约束
1. ✅ 约束框架：姿态分“动画值 local”和“约束后 applied”两层，约束按列表顺序生效；数值可打关键帧。
2. ✅ IK 约束；姿势工具 Ctrl 多选骨骼链用 CCD IK 摆姿势。
3. ✅ 变换约束。
4. ✅ 路径附件与路径约束。
5. ✅ 物理约束（状态由编辑器按时间推进，可烘焙为关键帧）。工程格式升级为 version 4。

### 阶段 4：皮肤 ✅
没有把附件整体搬进皮肤，而是用“皮肤占位”：插槽里的占位附件按名字从激活的皮肤取内容。
这样附件切换 / 变形关键帧仍按插槽附件索引工作，旧工程无需迁移。工程格式升级为 version 5。
已知限制：变形关键帧按占位记录，多个皮肤的网格拓扑不同时只对顶点数相同的皮肤生效。

### 阶段 5：导入导出 ✅
Texture Packer、Export Images（PNG 序列/精灵表/GIF）、Export Video（ffmpeg）、二进制导出、
Import Data / Import Project（合并）、PSD 导入。渲染用 core/raster 的软件光栅化，结果确定且可测试。
命令行：`Poseweaver --run <json|bin|atlas|png|jpg|sheet|gif|mp4|webm|avi|mov|merge|psd|engines> <路径>`。

### 阶段 6：音频 ✅
miniaudio 播放与解码（WAV / MP3 / FLAC）；播放时按事件触发声音，从中途开始播放会接上已在进行的声音，
速度改变音调，暂停即停止；Dopesheet 为每个有音频的事件画波形；导出视频时把音频事件混成一条音轨。
波形峰值、混音和 WAV 编码在 core/audio_mix（有单元测试）。

### 补充：动画混合 ✅
core/anim_state 是运行时式的 AnimationState：多轨道按序叠加（高轨道覆盖其关键帧的通道，可设轨道权重），
同轨道切换动画时交叉淡化（旋转走短路径，附件 / 绘制顺序 / IK 弯曲方向在一半处切换，变形与约束值插值），
动画队列（延迟默认相对上一动画结束减去混合时长）、空动画淡出到下层、循环中的事件收集。
编辑器的“混合预览”视图（Dopesheet 旁）驱动视口；任何编辑会自动退出预览。

## 当前优先级与格式兼容阶段

1.0.3 已补齐普通导出提交日志、启动时的后台恢复及修改保护；资源扫描后台化，提供数量和取消。新增编辑器性能工具，覆盖实际工程打开、拖动、播放界面 CPU、撤销和启动导出；共享只读像素并减少重复检查与配置刷新。11 组回归通过；大型性能结果仍为合成压力样例，生产级用户工程和物理断电验收待补。

1.0.2 已补齐：效果预览按实际姿态、几何与参数变化刷新，普通导出按工程记住配置并提供尺寸/内存预估；PNG/JPG 序列使用清单安全清理旧尾帧；图片和音频可批量重定位并整步撤销。新增双皮肤、IK、三个动作的完整机器人示例与 [上手教程](GETTING_STARTED.md)。9 组回归通过，机器人资源包完成 Godot 实机导入和播放检查；Unity 仍按既定安排保留为待实测。

1. **美术功能先补混合模式（已完成）**：四种常用插槽模式先覆盖从编辑到导出的完整流程，暂不增加模式关键帧、组混合和高级滤镜。
2. **格式兼容分阶段验收**：
   - **第一阶段（已完成）**：自有 JSON/二进制格式 1–8 读取，普通工程继续写 v5；使用新混合效果写 v6，修改光源或像素参数写 v7。PSD 导入保留四种支持的模式，不支持的模式给出具体警告。
   - **第二阶段（未实现）**：先锁定一个外部 JSON 格式的明确版本和样例集（优先评估 Spine JSON），只验收静态骨架、插槽、图片/网格、皮肤和绘制顺序；未知字段与不支持对象要有报告。
   - **第三阶段（未实现）**：再逐项支持动画曲线、颜色/附件/变形关键帧及约束。每个对象建立“源数据 → 导入文档 → 图片对比”固定样例，确认时间采样和坐标约定后才声明支持。
   - **第四阶段（未实现）**：验证导出和目标运行环境；报告无法表达的功能，避免把部分可读误称为完整双向兼容。
3. **性能先测量（CPU/GPU 基线已建立）**：`rigcore_bench` 测姿态、网格、剪裁、CPU 图片绘制与撤销 JSON 快照；`riggpu_bench` 通过实际视口绘制入口分开测绘制列表构建、CPU 提交和 GPU 执行，记录设备信息、分辨率与实际绘制命令数。下一步用真实大工程复现慢项，再决定优化，暂不重写渲染器或替换撤销结构。方法和原始数据见 [PERFORMANCE.md](PERFORMANCE.md)。
4. **Unity / Godot 接入（第一阶段已实现）**：共享 `.pwframes` 烘焙帧动画，统一原点、精确帧时长和分页；动作选择及独立循环、资源预算、按工程记住配置、后台进度与取消已接入。Unity 导入器/播放器、Godot 原生 `AnimatedSprite2D` 插件与示例随包提供。Godot 实机导入播放验证，Unity Editor 验证待补；1.1.0 新增 Windows x64 实时骨骼运行时、换肤、多轨混合和事件接口，Godot 导入/播放测试通过，Unity 待实测；见 [RUNTIME_INTEGRATION.md](RUNTIME_INTEGRATION.md)。范围和验收见 [ENGINE_INTEGRATION.md](ENGINE_INTEGRATION.md)。
5. **光源与像素（第一阶段已实现）**：单个 2D 点光源、像素化、色板限色、有序抖动和描边，支持保存、撤销、预览和导出烘焙。CPU / GPU 效果预览可选并记住选择，GPU 失败回退 CPU；导出保持 CPU。配套引擎插件识别最近邻采样。后续再评估完整 GPU 角色合成、法线、阴影、绘画工具及复杂工程性能；见 [LIGHTING_PIXELS.md](LIGHTING_PIXELS.md)。

## 风险与说明

1.0.1 已补普通图片/视频后台导出、进度与取消、暂存和提交回滚，以及撤销/重做共享内存预算。隔离安装、升级和卸载完成验收；Unity 仅准备工程与脚本，仍未实测。详细边界与记录见 [RELEASE_ACCEPTANCE.md](RELEASE_ACCEPTANCE.md)。

- **皮肤**会改动核心数据结构，越晚做迁移成本越高。所以排在约束之后、导出格式定稿之前。
- **物理约束、路径约束、Graph** 是单项最大的三块，各自需要专门的数值算法与交互。
- **视频导出**依赖用户本机安装的 ffmpeg，编辑器只负责找到它并把帧通过管道传进去。
- **与 Spine 数据格式互通**（读写 Spine 的 JSON）不在本表内，需要另行评估：
  Spine 运行时的许可证要求使用者持有 Spine 授权。

1.1.0 补齐独立分量时间/曲线、关联网格与皮肤独立变形，以及常用编辑的局部撤销。复杂结构和补偿事务保留全量快照。新数据使用工程格式 v8。

1.1.1 补齐 Godot 骨骼 PackedScene 导入与默认完整资源发布流程，Windows 独立程序播放和实际绘制通过。Unity 完成真实程序集编译，Editor 验收等待授权；修复首帧/自动播放失败保护和 Start 重载。
